## A02 — Module Call Map

Full Module Roster (44 modules, M-001–M-044 — extended to 48, M-001–M-048, by the 2026-07-25 addendum below), Internal Call Table, Startup Sequence, and Async Boundaries are in `discovery/components/A02_module_call_map.md`. Summary:

Corrected 2026-07-24 — the Module Roster in `discovery/components/A02_module_call_map.md` was always correct; this summary sentence had an arithmetic slip (previously stated 16/20) — that correction is unrelated to and predates this pass's four additions.
- **Methodology adaptation flagged for engineer sign-off (P2):** VIVE's UI is server-rendered (FastAPI + Jinja2), not a client-side SPA — the PBVI-011 `route`/`page`/`layout`/`component`/`store` taxonomy doesn't apply cleanly. FastAPI routers were classified `serving`; see the component file for full rationale.
- **Four STAGE-2-DIVERGENCE findings from the original extraction, plus one added 2026-07-25** — see A02 Section 4 for full detail:
  1. `VISION_PROMPT` (the primary extraction prompt documented in `document_understanding_engine.py`) is dead code for the currently active provider — `ClaudeSonnetClient` ignores the passed prompt and uses its own embedded prompt instead. **Confirmed as a real extraction-quality risk, not cosmetic:** `ClaudeSonnetClient` hardcodes `line_confidence = 0.75` on every row rather than eliciting a genuine per-row confidence from the model, which always clears the 0.60 human-review threshold regardless of actual certainty — silently defeating RULE-10's "never silently succeed" design for the two failure modes (mixed prefix patterns, unreadable pages) VISION_PROMPT was specifically written to catch. Also missing: any totals-row exclusion instruction (no code-level filter either), and semantic fallback mapping for most fields beyond invoice_number/outstanding_amount. Recommend P1/P2 RISK_REGISTER priority at Session E, not P3.
  2. The AI provider chain contradiction (Session A0's flagged 8-way disagreement) is now confirmed at the call-site level: `client_factory.get_ai_client()` with no argument resolves to `active_provider.json`'s `provider_chain[0]` = `"claude_sonnet"` → Claude Sonnet 4.6 is the actual executing primary. RULES.md, Implementation Context, and five separate code comments/docstrings all disagree with this and with each other.
  3. Blob Storage archival **is** wired end-to-end (`notebooks/01_document_intake.py` Step 8), contradicting Implementation Context's "Not wired into the pipeline yet" — this also corrects Session A0's own provisional note.
  4. No stale-job requeue logic exists in `web/queries.py`, despite Implementation Context Phase 3 explicitly specifying it — a genuine, code-confirmed gap, not just doc staleness.
  5. **[ADDED 2026-07-25]** The Event Grid auto-intake webhook (M-046, `web/routers/intake_trigger.py`) was found during this pass's security review to have **no authentication of any kind** — no signature check, no shared secret, no Azure AD token; the Event Grid "validation handshake" it does perform is a delivery formality, not auth. A second finding in the same review: the downstream `BlobStorageClient.download_pdf()` (M-039) derived the container to download from out of the caller-supplied blob URL rather than pinning it to the configured dropzone container. **Both are now fixed in code** (constant-time shared-secret check via `VIVE_EVENTGRID_WEBHOOK_SECRET`, hard-pinned container, plus a 100-event request cap) as of 2026-07-25 — see `discovery/RISK_REGISTER.md` R-009 for the full writeup and the **still-open deployment action item** (the secret isn't yet generated/configured on the actual Azure Event Grid subscription).
