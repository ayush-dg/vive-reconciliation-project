**Module:** UploadForm
**ID:** M-070
**Layer:** component
**Primary Responsibility:** Client-side upload workflow — drag/drop or browse a PDF, submit it via `multipart/form-data`, then automatically chain a silent extraction call and refresh the uploaded-statements table.

**Inputs (Props):** `{ initialDocuments: ApiDocument[] }` (type from `@/lib/documents`, out-of-scope M-011).
**Outputs (Rendered UI + Side Effects):**
- Renders a dropzone (drag-over/drag-leave/drop handlers, hidden file `<input type="file" accept="application/pdf">`, "Browse files" button, selected-file preview with size in MB, inline validation error), an upload form with a submit button, and an "Uploaded statements" table (File Name / Legal Entity / Uploaded / Action columns) with per-row Extract button or status badge.
- `handleSubmit`: validates a file is selected (else sets `fileError`); on submit, `POST /api/documents` (M-044) with `FormData` containing `file` and a **fixed** `legalEntityId` (`LEGAL_ENTITIES[0].id` — Legal Entity is no longer user-selected, per source comment, "engineer-directed simplification, 2026-08-30"); handles duplicate-upload and duplicate+legal-entity-mismatch response cases with distinct toast messages; on success, clears the file input, calls `refreshDocuments()` (`GET /api/documents`, M-044), and — unless it was a duplicate — automatically triggers `handleExtract(newDocumentId, { silent: true })` as a fire-and-forget call (not awaited) so the Upload button isn't blocked for the duration of extraction.
- `handleExtract(documentId, { silent? })`: `POST /api/documents/{id}/extract` (M-046); on HTTP 409 shows "already in progress" error + refreshes; on other failure shows parsed/fallback error toast; on success shows "Extraction started." toast unless `silent` is set (auto-chained case, since the upload success toast already covers it).
**State Consumed:** Reads `useToast()` (M-083) at lines 39, 65, 71, 74, 77, 115, 120, 124, 145. All other state (`documents`, `file`, `fileError`, `dragActive`, `submitting`, `extractingIds`) is local `useState`. Reads the static `LEGAL_ENTITIES` constant from `@/lib/legalEntities` (not in this session's module scope) for both the fixed default entity id and the display-name lookup in the table.
**Public Interface:** `export default function UploadForm({ initialDocuments }: { initialDocuments: ApiDocument[] })`; internal (non-exported) `formatUploadTimestamp`.
**Error Behaviour:** `handleSubmit`: on non-ok response, shows `data.error ?? 'Upload failed.'` toast, returns early (no refresh). On network/parse exception, shows a generic "Upload failed — check your connection..." toast. `handleExtract` follows the same 409/non-ok/exception pattern as M-068/M-076. No error is thrown to the nearest boundary (M-066) — all failures are toast-only; there is no inline `InlineLoadError` usage in this component (unlike M-068, M-072, M-074, M-076) since the initial document list is server-fetched once and only refreshed after actions, not independently retriable.
**Known Fragility:** `[NOTABLE]` `handleExtract(newDocumentId, { silent: true })` after upload is called with `void` (fire-and-forget, not awaited) inside the `finally` block's aftermath — `setSubmitting(false)` runs *before* this auto-extraction completes, deliberately, per the source comment, so a second upload isn't blocked; but this means the row's "Extracting…" state and the auto-triggered extraction's own error handling run fully asynchronously and independently of the upload flow's toast timing — a fast second upload could interleave toasts from two different documents' extraction attempts. The fixed `DEFAULT_LEGAL_ENTITY_ID = LEGAL_ENTITIES[0].id` means array-order changes to `LEGAL_ENTITIES` silently change which entity every new upload is assigned to. Duplicate-detection response shape (`duplicate`, `legalEntityMismatch` booleans) is parsed with optional chaining but not validated — a backend response missing these fields degrades to the "success" toast path silently.
**Change Impact:** Any change to `POST /api/documents` (M-044) response shape (`document`, `duplicate`, `legalEntityMismatch`, `error`) breaks this component's branching logic. Removing/reordering `LEGAL_ENTITIES` changes the default entity silently. Shares the extract-action pattern with M-068 and M-076 — a behavior change to the 409/error-handling convention in one should probably be mirrored in the others for consistency, though there's no shared abstraction enforcing that.
**Callers:** M-069 (UploadPage) renders this.
**Calls:** M-083 (useToast, many lines: 39, 65, 71, 74, 77, 115, 120, 124, 145); fetch `GET /api/documents` (lines 42, 106, → M-044); fetch `POST /api/documents` (line 106 — upload, → M-044); fetch `POST /api/documents/{id}/extract` (line 63, → M-046).
**Integration Points Used:** None (fetches internal API routes only).
