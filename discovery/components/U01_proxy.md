**Module:** proxy.ts
**ID:** M-043
**Layer:** route
**Primary Responsibility:** Next.js middleware that enforces the 30-minute idle-timeout authentication shell on every matched route, redirecting unauthenticated/expired requests to `/login` and refreshing the session cookie's `lastSeenAt` on every authenticated pass.

**Inputs:** Implicit — invoked by the Next.js middleware runtime (Edge) for every request whose path matches `config.matcher`. Reads the `vive_session` cookie (`SESSION_COOKIE_NAME`, from M-004) off `request.cookies`. No explicit params/body — the whole "input" is the incoming `NextRequest` and its cookie jar.
**Outputs:**
- Unauthenticated or expired session: `NextResponse.redirect('/login')` with the `vive_session` cookie deleted.
- Authenticated, non-expired session: `NextResponse.next()` (request proceeds to its target route) with `vive_session` re-set to a freshly signed token whose `lastSeenAt` is `Date.now()` (sliding-window refresh), using `sessionCookieOptions()` from M-004.
There is no error-status output — this module only ever returns a redirect or a pass-through; it cannot itself produce a 4xx/5xx.
**Public Interface:**
`export async function proxy(request: NextRequest): Promise<NextResponse>`
`export const config = { matcher: [...] }` — the Next.js middleware matcher array (a regex-based path exclusion list), not a callable, but part of this module's public contract since it determines which requests the framework routes through `proxy` at all.
**Error Behaviour:** No try/catch in `proxy` itself. `verifySessionToken` (M-004) is written to swallow all internal errors (malformed token, missing parts, crypto failure) and return `null` rather than throw, so a corrupt cookie is treated the same as "no session" -> redirect to `/login`. If `SESSION_SECRET` is unset, `signSessionToken`'s call to `getSigningKey()` throws synchronously inside M-004 — this is NOT caught here, so a request that reaches the refresh step (line 24) with `SESSION_SECRET` missing would throw an unhandled exception inside Edge middleware. NOT DETERMINABLE FROM SOURCE what Next.js's Edge runtime does with an unhandled throw in middleware (likely a framework-level 500), since that's outside this module's own code.
**Known Fragility:** [NOTABLE] The `config.matcher` regex is the single point of truth for which routes require auth — its own comment documents a past defect where public asset paths (e.g. `public/vive-logo.png`) were NOT excluded and got redirected to `/login`, breaking `next/image`'s optimizer (it received a redirect, not image bytes). Any new static-asset extension or new public route added without updating this regex will silently either (a) become unauthenticated if wrongly excluded, or (b) break asset loading if wrongly included. The matcher is a single large negative-lookahead regex — easy to get subtly wrong and hard to unit-test exhaustively. Also: this module trusts `SESSION_SECRET` to be present at runtime with no startup-time validation; a missing secret fails only on first request that needs signing, not at boot.
**Change Impact:** Governs access to every route in the `(app)` route group (M-064 and everything it renders — M-067 through M-083) — a matcher regression could either lock out legitimate authenticated traffic or expose protected screens unauthenticated. Any change to `SESSION_COOKIE_NAME`, `sessionCookieOptions()`, `signSessionToken`, `verifySessionToken`, or `isSessionExpired` in M-004 directly changes this module's behavior since it calls all four. Changing the idle-timeout window (`getIdleTimeoutMs()` in M-004) changes how aggressively this module redirects.
**Callers:** None via direct function call — invoked by the Next.js framework itself as Edge middleware for every request matching `config.matcher`. M-064 ((app)/layout.tsx) is protected by this module via the Next.js middleware matcher at the framework/routing level, not a direct function call.
**Calls:** M-004 (`src/proxy.ts:15,17,24,30` — `verifySessionToken`, `isSessionExpired`, `signSessionToken`, `sessionCookieOptions`)
**Integration Points Used:** None (routes through serving-layer modules) — N/A here since M-043 calls only infra module M-004, no serving-layer module and no external system directly.
