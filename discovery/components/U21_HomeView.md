**Module:** HomeView
**ID:** M-068
**Layer:** component
**Primary Responsibility:** Client-side Dashboard UI — renders summary stat cards and the recent-uploads table, with per-row Extract/Reconcile actions and a manual refresh cycle.

**Inputs (Props):** `{ initialDocuments: ApiDocument[]; stats: HomeSummaryStats }` (types from `@/lib/documents` and `@/lib/homeSummary`, both out-of-scope M-011/M-014 modules).
**Outputs (Rendered UI + Side Effects):**
- Renders a topbar ("Reports"), 4 stat cards (`data-testid="home-summary-stats"`, per-stat testids), and a statements table (`data-testid="home-statements-table"`) with columns Vendor/Period/Status/Uploaded/Action; empty state links to `/upload`.
- Per row: computes `homeDisplayStatus(doc)` — a Home-specific relabeling layer over `status_badge` (e.g. "Extracted" badge shown as "Success", "Reconciled" shown as "Done", and a "Failed" badge with `open_exception_count > 0` is *reinterpreted* as "Done" + a "Show exceptions →" link to `/exceptions/{vendorSlug}`, distinguishing a reconciled-with-exceptions document from a genuine extraction failure).
- Side effects: `handleExtract(documentId)` — `POST /api/documents/{id}/extract` (M-046); `handleReconcile(documentId)` — `POST /api/documents/{id}/match` (M-047); `refresh()` — `GET /api/documents` (M-044) + `GET /api/home-summary` (M-052) in parallel via `Promise.all`, updating local `documents`/`stats` state.
- Shows toasts via `useToast()` (M-083) for success/failure of both actions, including a specific message on HTTP 409 ("already in progress").
**State Consumed:** Reads/writes `toastStore` via `useToast()` (M-083) at lines 60, 88, 94, 97, 100, 117, 123, 126, 129. All other state (`documents`, `stats`, `extractingIds`, `reconcilingIds`, `loadError`) is local `useState`, seeded from props.
**Public Interface:** `export default function HomeView({ initialDocuments, stats: initialStats }: { initialDocuments: ApiDocument[]; stats: HomeSummaryStats })`; internal helpers `formatUploadTimestamp`, `homeDisplayStatus` (not exported).
**Error Behaviour:** `refresh()` never throws — a failed fetch (non-ok response or network exception) sets local `loadError` state, rendering `<InlineLoadError onRetry={refresh} />` (M-081), by design decoupled from the extract/reconcile try/catch blocks (per source comment) so a refresh failure after a successful action isn't misreported as an action failure. `handleExtract`/`handleReconcile` each: on HTTP 409 show a specific "already in progress" error toast + still refresh; on other non-ok, parse `{ error? }` from JSON (falling back to a generic message) and show error toast; on network exception, show a generic connection-error toast. No error is ever thrown to the nearest boundary (M-066) from this component's own logic.
**Known Fragility:** `[NOTABLE]` `homeDisplayStatus` is a *Home-specific* relabeling of the underlying `status_badge.badge` value — per its own comment, "other screens/logic (canReconcile, etc.) still use [the raw badge] unchanged." A future engineer changing `status_badge` semantics upstream (M-011/M-014) without checking this function risks silently breaking Home's "Done"/"Success" labels or the exceptions-link visibility logic, since it re-derives meaning from `badge === 'Failed' && open_exception_count > 0` rather than a dedicated field. `canExtract`/`canReconcile` gating logic (`doc.status === 'registered'` / `doc.status === 'processing' && badge === 'Extracted'`) is duplicated verbatim in `DocumentDetailView` (M-076) and `UploadForm`'s extract gating (M-070) — changing the rule in one place without the others creates inconsistent action availability across screens.
**Change Impact:** Any change to `ApiDocument` or `HomeSummaryStats` shape breaks this component's rendering. Changes to the extract/match API response shape (M-046, M-047) affect its error-message parsing. Removing `InlineLoadError` (M-081) or `useToast` (M-083) breaks its error/feedback UX.
**Callers:** M-067 (HomePage) renders this.
**Calls:** M-083 (useToast, many lines: 60, 88, 94, 97, 100, 117, 123, 126, 129); fetch `GET /api/documents` (line 69, → M-044); fetch `GET /api/home-summary` (line 69, → M-052); fetch `POST /api/documents/{id}/extract` (line 86, → M-046); fetch `POST /api/documents/{id}/match` (line 115, → M-047).
**Renders:** M-081 (InlineLoadError, conditional on `loadError`).
**Integration Points Used:** None (fetches internal API routes only).
